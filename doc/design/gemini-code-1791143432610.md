# Architectural Blueprint: Hybrid Merkle-Hilbert Spatial Chunk Tensor

## Executive Overview

The **Hybrid Merkle-Hilbert Spatial Chunk Tensor** is a persistent, purely immutable data structure designed to reconcile the competing demands of functional, version-controlled systems and high-performance numerical computing.

Standard functional tensor designs struggle with cache locality and SIMD vectorization during array transformations. Conversely, traditional strided tensor buffers require full memory copies ($O(N)$) for pointwise updates and lack built-in deduplication or structural identity checks.

By combining a **Merkle CHAMP prefix DAG** at the upper indexing tier with dense, **Hilbert-ordered spatial leaf chunks** at the storage tier, this architecture delivers:
* **$O(1)$ Structural Equality & Deduplication:** Via cryptographic/content-addressed node hashing.
* **$O(\log N)$ Pointwise Updates & Path Copying:** Structural sharing preserves unmodified subtrees across tensor versions.
* **High SIMD/L1-Cache Utilization:** Contiguous $N$-dimensional sub-cubes packed along Hilbert space-filling curves within leaf nodes.
* **Zero-Copy Slicing:** Range queries and spatial bounding boxes resolve to lightweight sets of immutable chunk pointers.

## 1. System Topology & Tier Separation

The architecture splits index management from numeric buffer execution across two explicit layers:

```
                      +----------------------------------+
                      |  Root Node (Merkle Hash: 0x9f3a) |
                      +----------------------------------+
                                  /          \
                                 /            \
            +-----------------------+     +-----------------------+
            | Branch Node (0x1a2b)  |     | Branch Node (0x8c7d)  |
            +-----------------------+     +-----------------------+
                     /         \                   /         \
                    /           \                 /           \
         +-----------------+  +-----------------+  ...        ...
         | Leaf Chunk A    |  | Leaf Chunk B    |
         | (32x32 Hilbert) |  | (32x32 Hilbert) |
         +-----------------+  +-----------------+
```

### Top Tier: Merkle CHAMP Prefix DAG
* **Routing Index:** Global tensor coordinates $(i_0, i_1, \dots, i_{k-1})$ map to a 1D spatial curve index ($H$). $H$ is used as a prefix bitstring for trie navigation.
* **Compressed Hash-Array Mapped Prefix-Tree (CHAMP):** Branch nodes utilize canonical bitmaps (`nodemap`) to eliminate null pointers and keep node arrays strictly packed.
* **Content Hash Invariant:** Every branch node hash is derived deterministically from its children:
  $$\text{Hash}_{\text{parent}} = \text{BLAKE3}\left(\text{Hash}_{\text{child}_0} \mathbin{\Vert} \text{Hash}_{\text{child}_1} \mathbin{\Vert} \dots \mathbin{\Vert} \text{nodemap}\right)$$

### Bottom Tier: Hilbert-Ordered Contiguous Leaf Chunks
* **Chunk Geometry:** $N$-dimensional spatial blocks aligned globally (e.g., $32 \times 32 \times 32$ floats, occupying $128 \text{ KB}$).
* **Spatial Memory Layout:** Within each leaf chunk, elements are arranged along a **Hilbert Curve** (or Morton Z-order) rather than row-major ordering. This maintains spatial compactness along all axes, optimizing multi-axis slicing and stencil calculations for L1/L2 cache lines.

## 2. Core Data Structures (Rust Reference Types)

```rust
use std::sync::Arc;

pub type MerkleHash = [u8; 32]; // e.g., BLAKE3 output

/// Contiguous leaf chunk containing raw numeric tensor elements.
#[derive(Clone, Debug)]
pub struct SpatialChunk<T, DIMS: const usize> {
    /// Global spatial origin of this chunk within the tensor [z, y, x]
    pub origin: [usize; DIMS],
    /// Extents of this chunk (e.g., [32, 32, 32])
    pub shape: [usize; DIMS],
    /// Pre-computed content hash over the byte representation of data
    pub chunk_hash: MerkleHash,
    /// Immutable, contiguous buffer of data points packed in Hilbert order
    pub data: Arc<[T]>,
}

/// Pointer variant allowing lazy evaluation, local cache, or remote fetching.
#[derive(Clone, Debug)]
pub enum NodeRef<T, ARITY: DIMS: const usize usize,> {
    Branch(MerkleBranchNode<T, ARITY, DIMS>),
    Leaf(SpatialChunk<T, DIMS>),
    Unloaded(MerkleHash),
}

/// Non-leaf branch node enforcing CHAMP structural packing.
#[derive(Clone, Debug)]
pub struct MerkleBranchNode<T, ARITY: DIMS: const usize usize,> {
    /// Bitmask indicating present child slots (CHAMP compression)
    pub nodemap: u64,
    /// Combined hash over all active child nodes
    pub node_hash: MerkleHash,
    /// Direct references to packed child nodes (length == popcount(nodemap))
    pub children: Arc<[NodeRef<T, ARITY, DIMS>]>,
}

/// Root handle representing an immutable tensor state.
#[derive(Clone, Debug)]
pub struct HybridTensor<T, ARITY: DIMS: const usize usize,> {
    pub shape: [usize; DIMS],
    pub root: NodeRef<T, ARITY, DIMS>,
}
```

## 3. Operational Mechanics & Complexity

| Operation | Mechanics | Time Complexity | Memory Allocation |
| :--- | :--- | :--- | :--- |
| **Pointwise Read** | Coordinates $(i, j, k) \to H \to$ Prefix trie walk $\to$ Hilbert index offset. | $O(\log_{\text{ARITY}} N)$ | Zero |
| **Pointwise Write** | Clone leaf chunk $\to$ mutate target element $\to$ recalculate chunk hash $\to$ path-copy parents. | $O(\text{ChunkSize} + \log N)$ | $O(\text{ChunkSize} + \text{TreeDepth})$ |
| **Structural Equality** | Compare root node `node_hash` values (`hash_A == hash_B`). | $O(1)$ | Zero |
| **Sub-cube Slicing** | Calculate chunk bounding box $\to$ extract matching `Arc<SpatialChunk>` handles. | $O(\text{Intersected Chunks})$ | Pointer array creation |
| **Deduplication** | Identical spatial sub-cubes resolve to existing `MerkleHash` instances in table. | $O(1)$ amortized | Zero |

## 4. Key Execution Workflows

### 4.1 Pointwise Mutation & Path Copying
When a value at index $(i, j, k)$ is modified:
1. Convert global coordinate $(i, j, k)$ to the 1D Hilbert index $H$.
2. Traverse down the CHAMP DAG to locate the target `SpatialChunk`.
3. Allocate a new `Arc<[T]>` for the target chunk, copying existing data and applying the update at the localized Hilbert offset.
4. Calculate `BLAKE3(new_chunk_bytes)`.
5. Reconstruct all `MerkleBranchNode` instances along the root path:
   * Retain unmodified sibling pointers by incrementing their atomic ref-counts (`Arc::clone`).
   * Recompute `node_hash` at each level up to the new root handle.

### 4.2 Spatial Range Slicing
To perform a range query $x[a:b, c:d, e:f]$:
1. Calculate the spatial bounding box $B = [a, b) \times [c, d) \times [e, f)$.
2. Intersect $B$ with global chunk boundaries to identify target chunk origins.
3. Traverse the Merkle DAG, pruning any branch whose spatial extent does not intersect $B$.
4. Return a `SubTensorView` struct containing an array of intersected `Arc<SpatialChunk>` references along with local offset metadata. No element array copies are performed.

## 5. Architectural Implementation Guidelines

1. **Chunk Sizing Target:**
   Set leaf chunk size between **32 KB and 256 KB** (e.g., $32 \times 32 \times 32 \times 4 \text{ bytes} = 131.072 \text{ KB}$). This fits comfortably within standard L2/L3 CPU cache sizes while preventing ballooning tree depth.

2. **Global Grid Alignment:**
   Enforce rigid, non-overlapping global chunk grids (e.g., origins strictly placed at multiples of 32). This guarantees canonical chunking: two tensors with identical spatial data will always generate identical chunk boundaries and matching Merkle hashes.

3. **Deferred Hash Computation:**
   In high-throughput pipeline operations (e.g., chained tensor arithmetic), defer Merkle hash recomputation until the tensor state is committed to a persistent store or checked for equality.

4. **Hardware SIMD Vectorization:**
   During local kernel operations (GEMM, convolutions), re-order or unroll Hilbert-ordered chunk buffers into temporary contiguous linear slices in L1 memory when invoking wide AVX-512 / NEON vector instructions.
